# 3개 브랜드 주차별 포털 지표 수집 설계

인생아구찜 · 삼대미역 · 어화락. 2026-08-25 기준 설계, 파일럿 검증 완료.

## 0. 주차 정의

ISO 주차, **월요일 시작 · 일요일 종료 · KST**. 모든 채널이 이 기준으로 맞춰진다.
수집 시점의 이번 주는 미완성 구간이라 항상 **지난주 일요일까지만 확정 저장**한다.

## 1. 지표를 두 종류로 나눈다

| kind | 뜻 | 예시 | 주차 처리 |
|---|---|---|---|
| **flow** | 그 주차에 발생한 양 | 검색지수, 블로그 발행 수, 플레이스 조회수, 매출 | 그대로 주차값 |
| **stock** | 그 시점의 누적 스냅샷 | 리뷰 수, 팔로워, 유튜브 누적 조회수, 매장 수 | 매주 찍어 **차분**해야 증분이 나옴 |

stock 지표는 오늘 안 찍으면 지난주 값이 영원히 복원되지 않는다. 착수 우선순위가 여기다.

## 3. 파일럿에서 확인된 함정 4개

1. **네이버 검색 API는 따옴표 정확일치를 지원하지 않는다.** `"인생아구찜"`과 `인생아구찜`의
   결과 수가 6,604건으로 동일했다. 후처리 필터링이 필수다.
2. **브랜드명 오염이 심하다.** 블로그 30건 표본에서 자사 글은 14건(47% 노이즈)이었다.
   "인생 아구찜"이 "내 인생 최고의 아구찜"이라는 일반명사구로 쓰이기 때문이다. 삼대미역은
   더 나쁘다. 최상위 결과가 경쟁사 "팔도미역" 글이었다. `keywords.json`의 exclude_any로 거른다.
3. **저검색 브랜드는 주차가 통째로 빈다.** 어화락은 52주 중 4주가 결측이었다. 데이터랩은 검색량이
   임계치 아래면 값을 반환하지 않는다. 0으로 채우면 추이가 거짓말이 된다.
4. **유튜브 API에 일일 쿼터가 있다.** 파일럿 중 실제로 쿼터가 소진돼 수집이 막혔다.
   유튜브는 주 1회 정해진 시각에만 호출한다.

## 4. 데이터 스키마

`data/weekly_metrics.csv`, long format 한 장으로 통일한다. 지표가 늘어도 컬럼이 늘지 않는다.

```
week_start, brand_id, brand, portal, metric_key, value, unit, kind, note, collected_at
```

`(week_start, brand_id, metric_key)`가 유일키다. 재실행하면 덮어쓴다.

## 5. 실행

### 최초 1회

```bash
winget install Python.Python.3.12
```

네이버 개발자센터에서 애플리케이션을 등록하고(검색 + 데이터랩 API 선택) 키를 환경변수에 넣는다.

```bash
setx NAVER_CLIENT_ID "발급받은_ID"
```

```bash
setx NAVER_CLIENT_SECRET "발급받은_SECRET"
```

### 매주

```bash
python collect.py --weeks 8
```

과거 52주를 한 번에 채우려면 `--weeks 52`. 로그인 벽 뒤 지표는 `manual_template.csv`를
그 주차용으로 복사해 값을 채운 뒤 `data/weekly_metrics.csv`에 붙인다.

Windows 작업 스케줄러에 매주 월요일 오전으로 걸어두면 A·D층은 손이 안 간다.
