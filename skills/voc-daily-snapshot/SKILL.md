# VOC 데일리 스냅샷

흩어진 고객의 소리를 하루 한 장으로 만든다. 마케팅팀 일일 회의에서 "어제 무슨 일이 있었나"를 60초 안에 답하게 하는 것이 목적이다.

## 무엇을 하나

| 단계 | 하는 일 | 산출물 |
|---|---|---|
| 1. 수집 | 5개 채널 → `MASTER_VOC` 시트 정규화 적재 | 원문 보존 행 |
| 2. 집계 | 일자×브랜드 / 월×매장 가중평균 누적 | `DAILY_AGGREGATE`, `MONTHLY_STORE_AGG` |
| 3. 보관 | 보관기간 지난 원문은 `ARCHIVE_VOC`로 이관 | 셀 한도 방어 |
| 4. 렌더 | JSONP로 요약만 내려보내고 원문은 클릭 시 조회 | 단일 HTML 대시보드 |

## 절대 규칙

1. **원문을 요약하지 않는다.** 목록에는 60자 스니펫만, 클릭하면 `raw_text` 전문이 그대로 뜬다. 요약은 뉘앙스를 죽이고, 뉘앙스가 VOC의 전부다.
2. **평균의 평균을 내지 않는다.** 집계 시트에 `rating_sum`과 `rated`를 따로 쌓고 나눈다. 일자별 평균을 다시 평균내면 건수가 다른 날이 같은 무게를 갖는다.
3. **집계는 덮어쓰지 않고 누적한다.** 원문이 이미 아카이브된 날짜에 리뷰가 늦게 도착하면, 그 날짜를 다시 계산하는 게 아니라 기존 합계에 더한다. 덮어쓰면 2,000건이 1건으로 바뀐다.
4. **개인정보는 시트에 넣지 않는다.** 매장명까지만. 점주 실명·개인 연락처, QR설문의 경품 발송용 성함·연락처는 매핑하지 않는다.
5. **API 키는 코드에 두지 않는다.** Apps Script의 Script Properties만 쓴다.

## 한계

- **본사/지사 권한 분리는 아직 걸려 있지 않다.** 현재 배포는 도메인 제한(조직 계정이면 전부 열람)까지만이다. 지사장이 로그인하면 전 매장이 보인다.
- 배포 URL은 Workspace 정책상 외부 호출이 302로 막힌다. 조직 계정으로 로그인된 브라우저에서만 데이터가 붙는다.
